# Plan 0.2.0 D: smarter grouping and a cheaper search

Part D of [0.2.0](0.2.0.md). All three changes are in the planner. None changes the format, and existing archives are
unaffected. A change is kept only where the measurements below show it helps.

## Where the code is

| Step | Code (`src/Osmium.Core/Planning/Planner.cs`) | Today |
|---|---|---|
| Grouping | `BuildGroups` | Files in the order extension → name → path; each file's units are appended to its group in that order, and `Layout` fills blocks in `g.Units` order. |
| Choice | `ChooseAsync` | Candidates → successive halving over the profile's rungs (`Objective` = size + `Lambda` × estimated decode seconds; `Lambda` is 0 unless the user asks for decode speed) → Store check for incompressible groups → `HillClimbAsync` → `RaceTopTwo` alternate. |
| Search | `HillClimbAsync` | Each step tries every untried neighbour on the full (last rung's) sample and moves to the best one if it is more than 0.01 % better. |

## D1: similarity ordering inside a group

- **What:** for groups of at least 3 files, reorder the files so that similar files are adjacent, which lets a solid
  block's long-range matches and context models see related data together. Keep each file's own units together and
  in their order (chunk-dedup units must not be split from their file).
- **Signature:** a 64-bit SimHash per file over 4-grams from a fixed sample (the first 64 KiB plus three 16 KiB
  windows at 1/4, 1/2 and 3/4 of the file; the whole file when it is smaller). The hash of each 4-gram is a fixed
  integer hash; every 4-gram counts once per occurrence. Integer arithmetic only.
- **Order:** greedy nearest neighbour. Start from the first file in today's order; repeatedly take the unvisited file
  with the smallest Hamming distance to the current one, ties broken by today's order. Groups with more than 20 000
  files keep today's order.
- **Where it applies:** text, UTF-16 text, code (x86, ARM64, .NET), binary and structured groups, from the Max
  profile up. Not audio, image (each file is its own group) or incompressible groups.
- **Explain:** one line per reordered group, e.g. `order: similarity (SimHash), 288 files`.
- **Determinism:** the order depends only on file contents and today's order, never on thread count or timing.

## D2: prefer the faster decoder on a near tie

- **What:** after the last rung, among the surviving candidates whose objective is within 0.1 % of the best, choose
  the one with the lowest `EstimateDecodeSeconds` for the group's size. The hill-climb then starts from it, and the
  top-two race uses the best remaining candidate as its alternate.
- **Why:** when `cm` and `lzma` produce archives within 0.1 % of each other, `lzma` decodes roughly 100× faster.
  The size cost is at most 0.1 % per group.
- **Explain:** `tie: chose X (decodes faster) over Y (0.04 % smaller)`.

## D3: screen search steps on the smaller sample (issue #2)

- **What:** when the profile has more than one rung (Ultra, Insane), keep the previous rung's sample and the
  incumbent's score on it. Each hill-climb step evaluates its neighbours on that smaller sample first and promotes
  to the full sample only the best `max(2, ceil(n / Eta))`, and of those only the ones within +0.5 % of the
  incumbent on the smaller sample. A move is accepted under the same rule as today (more than 0.01 % better on the
  full sample). Groups without a smaller rung keep today's behaviour.
- **Budget:** `SearchEvals` keeps counting neighbours generated, so a profile never tries more variations than today.
  The time saved comes from evaluating far fewer of them on the full sample.
- **Tests:** `PlannerSearchTests` (scripted trial runner) must keep passing; add tests that screening evaluates
  neighbours on the smaller sample, promotes the right number, never accepts a move that is not better on the full
  sample, and stays within the budget.

the change:

Keep a change only if it helps on at least one folder and costs no more than 0.1 % on the others. Timings are noisy
when other work runs on the machine: run A and B back to back and repeat once.
