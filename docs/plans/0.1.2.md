# Plan: Osmium 0.1.2

0.1.2 is a patch release: bug fixes, licensing compliance, a product site built from the real app, and documentation
that matches the code. **No `.osa` format change:** archives written by 0.1.2 must be byte-identical to 0.1.1 for the
same input, settings and pipeline. 0.2.0 ([0.2.0.md](0.2.0.md)) carries the compressor work.

This document is written for the agents doing the work. Each workstream owns a disjoint set of files, so the
workstreams can run in parallel git worktrees and merge without conflicts. The integrator merges in the order listed
and runs the full verification after each merge.

## Why

- **The website is a demo harness, not the product.** Its "working model" of the tray and the main window is HTML with
  invented data. The cluster key shows only dots, and its Show / Generate / Copy buttons do nothing. It loads Google
  Fonts, which sends every visitor's IP to Google. It draws a Windows-logo-like Start button, and makes claims that are
  unqualified or not true of the code.
- **The shipped files are not licence-compliant.** No download includes THIRD-PARTY-NOTICES. The portable ZIP and the
  single-file CLI do not include Osmium's own MIT LICENSE.
- **A code review found real bugs.** The most serious: the Settings page saves a stale snapshot, which reverts the
  cluster key and tray toggles changed elsewhere. Also: the "Verify every block" warning is inverted, and the planner
  re-reads whole blocks for every sample slice.

## Conventions for every workstream

- .NET 10, C# latest, nullable on. The build must stay at **0 warnings**.
- Tests: `dotnet test -c Release --project tests/Osmium.Core.Tests` and `--project tests/Osmium.Desktop.Tests`.
  Add tests for every fixed bug that can be tested on Linux.
- **WinForms code cannot run in this environment.** It is compiled here and exercised by CI on Windows
  (`--selftest-ui`). Keep UI changes small, compile-checked and defensive.
- **Determinism:** never change the output of an existing codec or filter. The golden-hash test (`ArchiveTests.cs`,
  `Golden.CmHash`) must stay green.
- **Commits:** one commit per logical fix, with a message saying what was wrong and how it is fixed. End each commit
  message with the attribution lines the session asks for.
- **User-visible text:** plain, specific, no apologies; name things as users see them.

## Workstreams

### S1 — App fixes (cluster key handling, keyboard, settings state)

**Owns:** `src/Osmium.App/**` except `SelfTest.cs`; `src/Osmium.Desktop/**`;
`src/Osmium.Core/Distributed/SecureChannel.cs` (only `ClusterKey`); `src/Osmium.Cli/ClusterCommands.cs`;
`tests/Osmium.Desktop.Tests/**`; a new `tests/Osmium.Core.Tests/ClusterKeyTests.cs`.

1. **Stale settings snapshots.** `TrayApp.SaveSettings` (TrayApp.cs ~132) must raise a `SettingsChanged` event.
   - `SettingsPage` (Pages.cs ~748) re-clones `_working` when it is shown, and on `SettingsChanged` when it has no
     unsaved edits.
   - `Apply()` saves only the descriptors the user edited: track the edited `SettingDescriptor`s, then copy those
     values onto a fresh clone of the current settings.
   - `ClusterPage` (Pages.cs ~664) reloads `_key` on activation and on `SettingsChanged`, unless the box holds unsaved
     edits.
   - Tray toggles must no longer be reverted.
2. **Key field.**
   - The Show button toggles its text between Show and Hide.
   - Generate unmasks the box so the new key is visible.
   - In the Settings renderer, the cluster key gets a Show toggle and fits a 70-character key (≈ 560 px at 96 DPI,
     scaled for DPI).
3. **Validation.**
   - `SettingAttribute`/`SettingDescriptor` gain string validation; the ClusterKey descriptor validates with
     `ClusterKey.Parse`.
   - An invalid key shows the parse error next to the field, on the Cluster page status line, and in the tray tooltip.
     Today it only goes to the log.
   - The tray "Lend this PC to the cluster" check reflects the setting (TrayApp.cs ~363).
   - "No workers answered" also mentions a key mismatch.
4. **`ClusterKey.Parse`** (SecureChannel.cs ~31):
   - remove all whitespace and dash-like characters (`-`, U+2010–U+2015, U+2212, U+00AD) and zero-width / BOM
     characters before decoding;
   - use an ordinal prefix check;
   - give a clear message for the characters the alphabet excludes (I, O, 0, 1).

   `SaveKey` stores the normalized `Parse(...).ToString()`. Unit tests cover: round trip, lowercase, spaces,
   line-wrapped, en-dash, non-breaking hyphen, BOM, truncated, typo (checksum), excluded characters.
5. **CLI worker.** `osmium worker` without `--key` refuses to start and explains that a key is needed and how to make
   one (`osmium keygen`), instead of inventing a throwaway key (ClusterCommands.cs ~66).
6. **Keyboard.**
   - **Enter:** single-line boxes get a KeyDown handler that runs their action — Save for the cluster key, Explain for
     the rules test path, Analyze or no-op for the archive output box, no beep for settings search and string settings.
   - **TuneDialog:** AcceptButton and CancelButton are set.
   - **Focus:** after `Navigate`, focus moves to the page's first control.
   - **Ctrl+Backspace:** in text boxes it deletes the previous word, and control characters are stripped from
     passwords and keys.
   - **Mnemonics:** `UseMnemonic = false` on `Ui.Heading`/`Ui.Text` and on labels showing file names, so "Rules &
     patches" displays its `&`.
   - **Shortcuts:** Ctrl+A selects all in lists; Delete removes, Enter opens; Ctrl+V pastes files on the Compress page;
     numpad 1–8 work like Ctrl+1–8; Ctrl+Q asks to confirm when there are unsaved Settings or Rules edits.
7. **Foreground.** Before forwarding to the running instance, the second instance calls
   `AllowSetForegroundWindow(ASFW_ANY)` (Program.cs ~33). `PasswordDialog` activates itself when shown and refocuses
   and clears its fields after a validation error.
8. **Smaller display bugs.**
   - **Inverted warning:** a setting's `WarningText` fires when the box is checked, so turning verification **on**
     warns. Add `WarnWhenOff`: "Verify every block" warns when it is turned off, Experimental warns when it is turned on.
   - **Number boxes** show no thousands separator ("46510", not "46,510").
   - **Tune dialog** shows choice and boolean codec parameters as choices, and sizes as sizes, not raw numbers.
   - **Rules JSON** is written with `JavaScriptEncoder.UnsafeRelaxedJsonEscaping`, so `+` and non-ASCII stay readable.
   - **Rules page** does not reload from disk over unsaved edits.
   - **Settings search** is debounced (≈ 250 ms).
   - **Restore defaults** on the Cluster category asks explicitly before discarding the key.
9. **About.** Add a "Help & about" section (a Settings category or a tray menu item, whichever is simpler) showing:
   - version, engine fingerprint and licence (MIT);
   - buttons to open `LICENSE.txt` and `THIRD-PARTY-NOTICES.txt` from the app directory, which S3 ships them to.

**Acceptance:** build at 0 warnings; Desktop and Core tests green, including new tests for key parsing, setting
validation, edited-only Apply (a pure function in Osmium.Desktop if possible) and WarnWhenOff behaviour.

### S2 — Engine 0.1.2 (planner fixes, golden vectors, forward compatibility)

**Owns:** `src/Osmium.Core/**` except `Distributed/SecureChannel.cs`; new files in `tests/Osmium.Core.Tests/`. Edit
existing test files only to add helpers if unavoidable.

1. **`Planner.BuildSample`** (Planner.cs ~496) reads only the needed range of each block with
   `BlockAssembler.AssembleRange`. Today it reassembles the whole block for every one of 16 slices.
   - The sample bytes must be **identical**; add a test comparing old and new sampling on a multi-block group.
2. **`HillClimbAsync`** checks memory with `Allowed(g, n, biggestBlock)`, as `ChooseAsync` does, not with
   `sample.Length`. Plans whose memory check passes today must not change; add a test.
3. **Planner tests with a fake `ITrialRunner`.** The fake is deterministic: size = a hash of the spec string, or a
   scripted table. The tests cover:
   - multi-rung halving keeps `max(2, ceil(n/Eta))`;
   - the hill-climb accepts improvements and stops;
   - the budget is respected;
   - Incompressible groups prefer Store within 1 %;
   - the Insane top-2 race;
   - determinism across thread counts.
4. **Golden vectors.** A new `GoldenVectorTests.cs` records, **on the unchanged code**, XxHash3 golden hashes for:
   - CM with `models` = Text, Binary, Default, All, and All+Record with `stride` = 12, at non-default `limit` / `lr` /
     `minlen` / `apm`;
   - **every filter**, at default and non-default parameters: x86, arm64, delta, transpose, pcm16, image, text.

   Use deterministic synthetic inputs. Each test also checks the round trip.
5. **Forward compatibility.** When a block uses a method id, parameter name or parameter value that this version does
   not know, the error says: "This archive needs a newer version of Osmium (block N uses <method/param>)". It does not
   say it looks corrupt.
   - In `ParamValues`/`Method.Normalize`, values outside the known range are **rejected on read and never clamped**;
     clamping stays only where specs are built from user or planner input.
   - Add tests.
6. **`osmium t` and `osmium info`** show that message for such archives, and the app's Archives page surfaces it.
   This includes `Extractor` paths in Core.

**Acceptance:** build at 0 warnings; all existing tests unchanged and green; the new tests green; an `osmium a … --profile max` archive of a test folder is byte-identical before and after S2. Compare
`osmium info` block tables and file hashes; the header timestamp may differ.

### S3 — Licensing and packaging

**Owns:** `THIRD-PARTY-NOTICES.md`, `LICENSE`, `Directory.Build.props` (Copyright only), `build/publish.ps1`,
`installer/osmium.iss`, `src/Osmium.Cli/Program.cs` (the `license` command and the password prompt only).

1. **`THIRD-PARTY-NOTICES.md`** gets the full notices, each with copyright lines and licence text:
   - **ZstdSharp.Port** (MIT, Oleg Stepanischev), plus **zstd** (BSD-3-Clause, Meta Platforms);
   - **SharpCompress** (MIT, Adam Hathcock), plus the **Bouncy Castle** MIT notice it carries and its credit to
     XZ.NET and managed-lzma;
   - **LZMA-SDK NuGet package** (MIT, Mihir Mone), wrapping Igor Pavlov's **public-domain** LZMA SDK;
   - **System.IO.Hashing** 10.0.x (MIT, .NET Foundation and contributors);
   - **.NET runtime and Windows Desktop runtime** (MIT), with a pointer to the runtime's own THIRD-PARTY-NOTICES,
     which is now shipped;
   - **Inno Setup**, for the installer only, under its licence.

   Copy licence texts from the package contents in `~/.nuget/packages` where present. Otherwise use the standard SPDX
   text, with the copyright line from the package metadata. Pin the Inno Setup version installed in CI, e.g.
   `choco install innosetup --version 6.x.y`, and say which version in the notices.
2. **Ship notices everywhere.** `publish.ps1` copies `LICENSE` → `LICENSE.txt` and `THIRD-PARTY-NOTICES.md` →
   `THIRD-PARTY-NOTICES.txt` into the publish folder. It also copies the .NET runtime's `LICENSE.TXT` and
   `THIRD-PARTY-NOTICES.TXT` from the runtime pack (`dotnet --list-runtimes` / the pack directory) as
   `dotnet-LICENSE.txt` and `dotnet-THIRD-PARTY-NOTICES.txt`.
   - The portable ZIP and the installer include all of them. The installer installs them.
   - The release job attaches `LICENSE.txt` and `THIRD-PARTY-NOTICES.txt` next to the single-file CLI. This needs a
     small `ci.yml` artifact-path addition; **coordinate with S4**, which owns `ci.yml` (S3 states the exact paths in its
     report).
3. **CLI.** `osmium license` prints Osmium's licence and the third-party notices, from embedded resources so that the
   single-file exe carries them. `osmium version` prints a "MIT licence; see `osmium license`" line.
4. **`Directory.Build.props`:** `<Copyright>Copyright (c) 2026 Osmium contributors</Copyright>`.
5. **Installer:** add an inbound firewall rule for UDP 46511 (discovery), next to the existing TCP 46510 rule, with
   matching uninstall cleanup.
6. **CLI password prompt** (Program.cs ~218):
   - ignore control and non-printable keys (arrows, Tab, Esc, dead keys);
   - Ctrl+C cancels;
   - Backspace works.

**Acceptance:** build at 0 warnings; `osmium license` prints all notices; `publish.ps1 -SkipInstaller` on Linux
produces a portable ZIP containing the four licence files; the `.iss` compiles in CI.

### S4 — Real self-test screenshots and CI

Starts after S1–S3 are merged.

**Owns:** `src/Osmium.App/SelfTest.cs`, `.github/workflows/ci.yml`.

1. **SelfTest renders real states only — no invented names, numbers or paths.**
   1. Create a deterministic sample folder under `%TEMP%\Osmium sample`:
      - a text file built from Osmium's own licence text;
      - a CSV of generated rows;
      - a 24-bit BMP gradient;
      - a 16-bit stereo WAV tone;
      - a copy of `Osmium.Core.dll`;
      - a PNG saved through System.Drawing.
   2. Add the folder on the Compress page and run the real Analyze.
   3. Run a real job with profile `max` through `JobManager` and wait for it, so the Jobs page shows a real finished job
      and its planner log.
   4. Open the produced archive on the Archives page.
   5. Run Lab on the WAV with profile `max`.
   6. Load the example rules (the "Add example" content).
   7. Generate a throwaway cluster key and show it **unmasked**.
   8. Capture the tray menu as an image (`ContextMenuStrip`, shown off-screen, `DrawToBitmap`).
   9. Capture the password dialog with an empty box.
2. **Fixed-size rendering.** Render the main window's **client area** (navigation rail and page) at a fixed
   1180 × 760 through a child-control host, so the runner's 1024 × 768 desktop does not clamp it. Do the same for
   dialogs. Output: light and dark PNGs plus a `manifest.json` listing each file, size and caption.
3. **`ci.yml`:**
   - After the x64 self-test on `push` to `main` (never on `pull_request`), a job with `contents: write` force-pushes
     the PNGs and `manifest.json` to an orphan branch `screenshots`, with a `concurrency` group.
   - Add an **ARM64** job on `windows-11-arm`: build, tests, CLI smoke test with the arm64 publish.
   - Add a **site** check: `python3 tools/site/build.py --check` fails if `docs/index.html` is not regenerated.
     Enable it after S5 lands.
   - Add the licence files from S3 to the release assets.

**Acceptance:** CI green on all jobs; the `screenshots` branch contains about 2 × 14 real PNGs; the integrator
fetches and reviews them.

### S5 — Site from the real product, with a legal pass

The integrator does this after the screenshots exist.

- **Generator in the repo.** `tools/site/template.html` and `tools/site/build.py` produce `docs/index.html` from:
  - `docs/benchmarks-*.json`;
  - planner outputs in `tools/site/data/`;
  - the screenshots, copied from the `screenshots` branch into `docs/img/` as optimised PNG / WebP, light and dark,
    used through `<picture>` with `prefers-color-scheme`.
- **Fonts.** Self-host Anybody, Instrument Sans and Martian Mono (variable woff2, Latin subset) in `docs/fonts/`, with
  their OFL licence files. **No third-party requests.**
- **Content.** Real screenshots replace every mock-up: no fake taskbar or Windows-like logo, no invented PCs, paths or
  jobs. Headings and claims are qualified:
  - "smallest in our mixed-folder benchmark";
  - "every block is verified by default";
  - "trial results from workers are spot-checked; returned blocks are fully verified";
  - the extraction estimate is shown "after compressing and in `osmium info`";
  - "x64 and ARM64 builds; ARM64 is tested in CI" only once S4 adds that job;
  - Windows 11 and Windows 10 (1809 or later).
- **Footer and notices:**
  - **Licence:** MIT, provided "as is" without warranty; keep backups and test archives before deleting originals.
  - **Third-party notices:** link.
  - **Trademarks:** "Windows and .NET are trademarks of the Microsoft group of companies; 7-Zip, ZPAQ, xz, Zstandard,
    Brotli, bzip2, lrzip and zip belong to their respective owners; Osmium is an independent project, not affiliated
    with or endorsed by them".
  - **Privacy:** "no cookies, no analytics, no third-party requests; hosted on GitHub Pages, whose privacy statement
    applies to server logs".
  - **Benchmark conditions:** machine, tool versions, date; results vary.
- Keep `noindex`.
- `docs/_config.yml` names the theme explicitly, so `head-custom.html` (noindex for the rendered Markdown) is applied.

### S6 — Documentation truth pass and release

The integrator does this.

- **BLUEPRINT.md** describes the code as built. Unbuilt ideas move to ROADMAP: PE-section sample windows, Mach-O/PDF
  sniffing, faster-decoder tie-break, SimHash ordering.
- **README, BENCHMARKS and ROADMAP** claims are qualified as on the site.
- **CHANGELOG** gets a 0.1.2 section. **CHECKLIST** is updated.
- **Tools move into the repo:**
  - `tools/settingsdoc/` regenerates `docs/SETTINGS.md`;
  - `tools/bench/` documents and rebuilds the benchmark corpora, with SHA-256 manifests;
  - `tools/site/` holds the site generator.
- **Release.** Bump the version to 0.1.2, push `main`, and wait for CI to go green. The owner publishes the v0.1.2
  release in GitHub's UI; CI attaches the files.

## Merge order

S2 → S3 → S1 → (push, CI) → S4 → (CI, screenshots) → S5 → S6.

S2 and S3 touch nothing S1 touches. Owners of shared lines: S1 owns the app; S3 owns `Program.cs`; S4 owns `ci.yml`.
