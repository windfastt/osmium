0.2.0 is a minor release that bundles every improvement since 0.1.1. It is written for the agents doing the work:
each part lists workstreams with disjoint file ownership, so they can run in parallel git worktrees. The integrator
merges, runs the full verification after every merge, and keeps this index current.

## C — `osmium salvage`

Every frame header carries magic, frame number and CRC ([FORMAT.md](../FORMAT.md)), so a damaged archive can be
scanned for intact blocks.

- `osmium salvage <archive> <dest>` scans for frame headers, decodes every block whose header, payload hash and raw
  hash check out, and reports every damaged block.
- If the index is intact, it writes every file whose blocks are all intact, and lists the files it lost.
- If the index is damaged, it writes the contents of each intact block as `block-<n>.bin`, with the block's
  pipeline and size.
- Encrypted archives need the password; the GCM tag authenticates each frame.
- Tests corrupt archives at many offsets (header, a block, the index, the footer) and check that every undamaged
  file is recovered byte-identically and that nothing damaged is ever written as if it were good.

## D — Smarter grouping and a cheaper search

Details: [0.2.0-d-grouping.md](0.2.0-d-grouping.md).

- **Similarity ordering inside a group:** SimHash over sampled 4-grams, greedy nearest-neighbour for ≤ 20 000
  files, ties by extension, name and path, so similar files sit next to each other in a solid block.
- **Tie-break:** when two candidates are within 0.1 %, prefer the faster decoder.
- **Search screening** (issue #2, moved here from part B because it is planner work): each search step tries its
  variations on the previous, smaller sample first and promotes only the best few to the full sample.

All three must stay deterministic. Each is kept only where the benchmark folders show it helps.

## E — App and CI

- **Recycle Bin option** ([details](0.2.0-e-recycle.md)): a setting "After a verified compression, move the
  originals to the Recycle Bin", off by default, using the shell's recycle API so files can be restored. Never when
  verification is off or the job failed, never for a folder that holds anything that was not archived, and never a
  permanent delete (drives without a Recycle Bin are skipped, and the shell is stopped from deleting what it cannot
  recycle).
- **ARM64 in CI:** an ARM64 job on `windows-11-arm` runs the tests and the CLI smoke test, so the site can say that
  ARM64 is tested.

## Release

When every part is merged:
- the version is 0.2.0;
- CI is green on Linux, Windows x64 and ARM64;
- benchmarks are re-run, and BENCHMARKS, the site and the README carry the new numbers;
- CHANGELOG and ROADMAP are updated.

The owner publishes v0.2.0 in GitHub's UI, and CI attaches the downloads.
