File compressor for Windows
Named after the densest natural element, 22.59 g/cm³

As small asyou have time for.

Osmium lives in the notification area and packs files into .osa archives. It works out what each file is and gives every kind of data its own pipeline. From the Max profile up it races codecs on samples, and from Ultra up it also tunes their settings. Give it more time and it brings in context mixing and, once you pair them, other PCs on your network.

Benchmarks · 2 folders · 8 other tools in 9 settings · every archive unpacked and compared

Smallest in our mixed-folder test

Each tool compressed the same two folders at the strongest setting people commonly use, and every archive was unpacked and compared with the original, file by file. In this test Osmium made the smallest archive of the mixed folder, which includes generated files; on the folder of program files, ZPAQ and lrzip made smaller ones. Against 7-⁠Zip -⁠mx9, Osmium's smallest archive was 3.2 % smaller on the program files (Ultra: 18 min 47 s to compress and 7 min 39 s to extract, against 33 s and 1.9 s) and 15.2 % smaller on the mixed folder (Insane: 17 min 29 s and 34 s, against 2.0 s and 0.3 s). Bars show the archive size as a share of the original; shorter is better.

How it was measured

Stream compressors got a tar of the folder. 7-Zip, ZPAQ, zip and Osmium archived the folder directly. xz and Zstandard ran single-threaded, because their multi-threaded modes split the input and lose ratio. The other tools used their default threading and Osmium all four cores, so the times are not at equal thread counts. Percentages compare with 7-⁠Zip -⁠mx9 (LZMA2, 256 MB dictionary) unless another tool is named. The mixed folder includes four files generated for the test: a CSV, 12-byte telemetry records, a WAV and a BMP.

Where Osmium loses

On program files, ZPAQ -m5 and lrzip beat Ultra: their models for x86 code are stronger than Osmium's today, and closing that gap is next on the list. There, Balanced, the default, and Max make larger archives than 7-⁠Zip -⁠mx9; Max only matches xz, since both are LZMA with a branch filter. Fast is larger than zip on the mixed folder.

The cost of the smallest file

Context mixing decompresses about as slowly as it compresses. After compressing, Osmium estimates the extraction time and memory, and osmium info shows the estimate for any archive; for context-mixing archives the real time can be about twice the estimate. Max uses no context mixing: it extracted the mixed folder in 0.5 s and the program files in 5.2 s.

Conditions

Measured on 24 November 2026 on one machine (4 vCPU Intel Xeon at 2.3 GHz, 16 GB RAM, Linux 6.18, .NET 10) with Osmium 0.1.1, Info-ZIP zip 3.0, bzip2 1.0.8, Brotli 1.1.0, Zstandard 1.5.5, xz 5.4.5, 7-Zip 23.01, lrzip 0.651, ZPAQ 7.15. Times are wall-clock seconds on that machine. Full tables and commands: BENCHMARKS.md; the SHA-256 of every file measured: benchmarks-0.1.1-corpus.sha256.

How it works · nine stages · every decision written to the archive's planner log

It reads the files before it packs them

Most archivers run one algorithm over everything. Osmium sorts files by what they contain and plans each group separately, then proves every block decodes before it writes anything.

Scan

Walks the inputs, applies exclude patterns, reads sizes and timestamps.

Analyze

Signatures (PE, ELF, WAV, BMP, PNG…), entropy, a zstd-1 probe and record stride.

Rules

Your per-file patches and rules force, forbid or tune pipelines.

Dedup

Identical files are stored once. Insane also finds repeated chunks inside and across files.

Group

Files with the same kind of data share solid blocks, aligned to their record size.

Plan

Balanced uses a fixed pipeline per kind. From Max up, candidates race on samples and the losers drop out; from Ultra up, the samples grow each round and the winner's parameters are hill-climbed.

Compress

Blocks run in parallel inside a memory budget, on this PC or on paired workers.

Verify

Every block is decoded and compared byte for byte before it is written.

Commit

Frames are written in order, the archive is read back, then renamed into place.

The app · tray icon · 8 pages · 64 settings in 11 categories

It lives next to the clock

Osmium starts with Windows and waits in the notification area. The ring fills while a job runs; hover it for the phase and percentage, right-click it for everything else. Drop files on the window, or right-click them in Explorer.

The app has eight pages — Compress, Jobs, Archives, Lab, Rules, Cluster, Settings and Log — and a tray menu with the default profile, recent jobs, pause, watch folders and lending this PC to a cluster.

Per-file control · patches · rules · pipeline syntax · 37 codec and filter parameters

Override anything, per file

Automatic planning is the default, never the limit. Patch one file from its right-click menu, keep a rule for a whole kind of file, or type the pipeline yourself. osmium explain shows which rule or trial decided each block.

Patch a file

Right-click a file on the Compress page. Tune… builds its pipeline stage by stage; Deep auto-tune… searches for it.

  • Tune…
  • Deep auto-tune…
  • Store as-is
  • Exclude
  • Clear patch
  • Save patch as global rule
  • Open containing folder

Write the pipeline

Filters, then one codec, with any parameter you want to pin.

# 12-byte records: delta per field, then LZMA
osmium a out.osa data ^
  --pipeline "delta(stride=12)+lzma(dict=128M,lc=0,lp=2,pb=2)"

# x64 code: branch converter, then context mixing
x86+cm(mem=24,models=4095)

# 16-bit stereo WAV: predictor after the 44-byte header, then CM
pcm16(offset=44,channels=2,lms=32)+cm

Keep a rule

Rules live in %APPDATA%\Osmium\rules.json. Every decision they make is recorded with its source.

{ "id": "logs",
  "match": { "globs": ["**/*.log"],
             "minSize": 1048576 },
  "actions": { "params": {
      "ppmd.order": "16",
      "lzma.dict": "256M" } } }

Borrow the other PCs in the house

Insane spends most of its time racing pipelines. Pair a few idle machines and the trials and the heavy blocks spread across them, while your PC keeps the final say.

Worker PCSame engine version, same keyworker
  • Workers authenticate with the shared key (mutual HMAC over an ECDH handshake) and must run the same engine version.
  • They see the contents of the blocks they compress, never file names. Pair only machines you trust.
  • Every block a worker compresses is decoded and compared on your PC before it is written; trial results from workers are spot-checked. A worker that returns a wrong result is quarantined.

  1. Make a key once

    Share the OSM1-… key with the machines you want to pair.

    osmium keygen

  2. Start a worker on each helper

    Or use Lend this PC to the cluster in its tray menu.

    osmium worker --key OSM1-…

  3. Compress with workers

    With --workers auto, Osmium looks for workers on the local network. Discovery across several PCs is not yet covered by our tests.

    osmium a big.osa D:\data --profile insane ^
  --workers auto --cluster-key OSM1-…

Safety · .osa format 1.0 · XXH128 per block and file · CRC32 per frame header

Checked before it is written

Smaller files are worthless if they do not come back intact. By default, each block is decoded and compared before it reaches the disk, and the finished archive is read again before it replaces anything. Verification can be switched off (Settings, or --no-verify); we recommend leaving it on.

HeaderMagic, format version, TLV extensions, CRC32
OBLK framePipeline descriptor, sizes, XXH128 of the raw data, XXH3 of the payload
OBLK frameOne per solid block, in plan order
···
IndexFiles, folders, timestamps, per-file hashes, dedup segments. Encrypted, names included, when a password is set
OSAEFooter: index offset and length

Layout of an .osa file, not to scale. Every frame header carries its own magic, number and CRC, so damage is reported block by block and never decoded silently.

Verified by default

Every block is decoded and compared with its input before it is written, including blocks compressed by a worker.

Atomic and change-aware

Archives are written to a temporary file, re-read, then renamed into place. A file that changes while it is read is detected.

Encrypted, names too

AES-256-GCM with PBKDF2-SHA512 and HKDF. With a password, file names, pipelines and contents are encrypted. The block count, block sizes, the version of Osmium that wrote the archive and whether experimental features were used stay visible.

Safe extraction

Paths that try to leave the target folder are refused, and the Mark of the Web is carried over to extracted files. 0.1.1 misses files the archive marks read-only; 0.2.0 fixes this.

Same output everywhere

The context-mixing codec is integer-only. CI checks a golden hash on Linux and Windows.

Extraction cost, stated

After compressing, and for any archive in osmium info or on the Archives page, Osmium estimates how long extraction will take and how much memory it needs. For context-mixing archives the time estimate can be half the real time: about 4 minutes estimated, 7 min 39 s measured for Ultra's archive of the program files.

Roadmap · after 0.1.1 · measured gaps first

What comes next

The benchmarks above show where Osmium still loses. Those gaps come first; everything else waits until it has a prototype and a number.

Next

Beat ZPAQ on program files

On 124 MiB of Windows DLLs and EXEs, ZPAQ -m5 is 6.2 % smaller than Ultra. Osmium CM needs stronger models for x86 code: E8/E9 limited to PE code sections, bit-history counters, a two-layer mixer, and opcode and ModRM contexts.

ZPAQ -m525.6 %
lrzip -z26.5 %
Osmium Ultra27.3 %
xz -9e28.8 %

Done when the gap shrinks measurably without losing ground on the mixed folder, and the codec stays integer-only and deterministic.

Next

Faster planning for Ultra and Insane

In a timing run on the mixed folder, Ultra spent 292 of its 346 seconds planning, mostly trying parameter variations on the largest sample. The search earns its keep, shrinking each group by 2–8 %, so it stays.

The plan: try each variation on the previous, smaller sample first and send only the best few to the full sample. Insane, whose largest sample is 16 MiB, gains the most.

Done when plans stay deterministic, sizes stay within about 0.2 %, and planning time drops.

Planned

  • Recompress compressed files. Bit-exact re-deflate for PNG, ZIP, DOCX and PDF, and lossless JPEG recompression. Today they are stored as-is.
  • Repair and grow archives. osmium salvage, recovery records, append and update, multi-volume.
  • Deeper Windows integration. A top-level Windows 11 context menu and notifications with actions.
  • Signed builds, so Windows can verify who published them.

Exploring

  • Faster context mixing. Integer SIMD inner loops, aiming for 1.5–2× with identical output.
  • Smarter grouping. Similar files next to each other, and different pipelines for regions of one file.
  • Cluster. Passphrase pairing, IPv6 discovery, a second worker double-checking context-mixing blocks.

The full list, with definitions of done: ROADMAP.md.
